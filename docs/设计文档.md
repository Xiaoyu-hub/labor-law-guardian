## 一、选题与定位

**一句话定位**：面向高校学生与新就业劳动者的「劳动法律风险自查 + 权益计算 + 维权路径导航」一体化普法工具。

**为什么要做这个**（选题论证）：

1. **法律教育落点明确**：把《劳动合同法》《劳动法》《社会保险法》《劳动争议调解仲裁法》《工伤保险条例》《职工带薪年休假条例》里"劳动者最需要但最不熟"的条文，变成可交互的自查动作，而不是背条文。
2. **痛点真实**：2026 届毕业生秋招签约高峰，实习/试用期协议、三方协议、劳动合同中的违法条款（超长试用期、不缴社保、竞业限制无补偿、随意解除）高频出现，学生普遍"看不懂、不敢问、不知道去哪维权"。
3. **演示友好**：输入一段合同文本 → 秒出风险报告；输入工资工龄 → 秒出应得金额；选一个纠纷类型 → 秒出维权时间线。三个动作都能在 30 秒内完成，视觉反馈强。

## 三、技术选型评估

| 方案 | 成本 | 演示效果 | 风险 | 结论 |
|---|---|---|---|---|
| A. Vite + Vue/React 单页 | 中高 | 好 | 演示需 `npm run dev` / 构建产物；现场无网络时 CDN 依赖可能挂 | ✗ |
| B. Node/Express + 数据库 + 前端 | 高 | 一般（后端不可见） | 端口/数据库进程是最常见翻车点 | ✗ |
| C. Python Flask 后端 + 前端 | 高 | 一般 | 同上，且本机 Python 环境有限制 | ✗ |
| D. **纯静态前端（原生 HTML/CSS/JS，零依赖零构建）** | 低 | **好**（UI 全自绘、秒开、无外部请求） | 无 | **✓ 采纳** |

**选 D 的关键理由**：
1. 双击 `index.html` 即可演示（`file://` 也能跑），**不依赖网络、不依赖任何 CDN、不需要装环境**——演示零风险。
2. 所有图表用原生 SVG 手绘（环形评分仪表盘、柱状图），不引第三方库。
3. 同一份代码可零改动部署到 GitHub Pages，满足"线上软件"的可访问性要求。
4. 逻辑全部是**可解释的规则引擎**，输出能逐条对应到法条，符合法治教育"讲清依据"的要求。

**约束**：不使用 ES Module（`file://` 下会因 CORS 加载失败），改用传统 `<script>` + 全局命名空间对象 `LJ`。

## 五、核心算法设计

### 5.1 合同体检规则引擎（`engine-check.js`）

规则条目结构：

```js
{
  id: 'PROBATION_OVER_6M',
  category: '试用期',
  severity: 'high',              // high | medium | low
  pattern: /试用期[^。；\n]{0,20}?(\d+|[一二三四五六七八九十]+)\s*(个月|月)/g,
  verify: (m, text, ctx) => ... // 二次判定：结合合同期限/补偿表述等上下文，降低误报
  law: ['劳动合同法 第十九条'],
  title: '试用期超过法定上限',
  advice: '劳动合同期限三年以上或无固定期限，试用期最长 6 个月；请改为不超过法定上限。'
}
```

流程：`原文 → 逐规则 global 正则扫描 → verify() 复核 → 命中项按 index 排序 → 重叠去重 → 生成高亮 HTML + 报告卡片 + 评分`。

评分：`score = 100 - Σ(high:22 / medium:10 / low:4)`，下限 5；≥85 低风险，60–84 中风险，<60 高风险。
当前规则库共 **47 条**（解除与终止 8 / 加班与工时 7 / 工资支付 7 / 试用期 6 / 社会保险 5 / 争议解决 4 / 违约金赔偿 3 / 竞业限制 3 / 工伤劳动保护 2 / 女职工保护 2）。

### 5.2 权益计算引擎（`engine-calc.js`）

- 日工资 = 月工资 ÷ 21.75（劳社部发〔2008〕3 号）；小时工资 = 月工资 ÷ 21.75 ÷ 8
- 加班费 = 工作日加班 h × 1.5 × 小时工资 + 休息日加班 h × 2 × 小时工资 + 法定节假日加班 h × 3 × 小时工资
- 经济补偿 N：满 1 年 1 个月，6 个月以上不满 1 年按 1 年，不满 6 个月按 0.5 个月；月工资 > 当地社平工资 3 倍时按 3 倍封顶且年限 ≤ 12 年
- 违法解除赔偿金 = 2 × N
- 未签书面合同双倍工资 = 月工资 × 超期月数（自用工满 1 个月的次日起算，最多 11 个月）
- 试用期法定上限：3 个月≤期限<1 年 → 1 个月；1 年≤期限<3 年 → 2 个月；≥3 年/无固定期限 → 6 个月；期限<3 个月或完成任务为期限 → 不得约定
- 未休年假折现 = 未休天数 × 日工资 × 300%（含正常工资，实际额外支付 200%，报告中两种口径都标注）
- 工伤停工留薪期工资 = 月工资 × 停工月数（原工资福利待遇不变，一般 ≤12 个月，经鉴定可延长 ≤12）
- 生育津贴 = 单位上年度职工月平均工资 ÷ 30 × 产假天数（未参保由单位按产假前工资支付）

### 5.3 维权导航（`roadmap-data.js`）

每种纠纷类型输出：`纠纷说明 → 时间线节点（协商/调解/仲裁/诉讼，含时限与要点）→ 关键时限卡片 → 材料清单 → 举证责任 → 风险提示`。

## 八、v2 在线功能扩展（Flask + SQLite 后端，2026-10-11 追加）

### 8.1 需求与取舍

v1 纯静态版满足「演示零风险」但缺「个人学习闭环」：体检/计算结果看完即丢，闯关成绩无记录，
没有学习行为沉淀。v2 增加一层本地后端，把学习行为变成可追溯、可统计、可交流的数据：

| 功能 | 数据表 | 说明 |
|---|---|---|
| 注册/登录 | `users` | session 会话 + PBKDF2-SHA256（20 万次迭代）加盐散列 |
| 体检历史 | `check_history` | 合同全文 + 命中数 + 评分 + 风险等级 + 发现明细（JSON） |
| 计算历史 | `calc_history` | 输入 + 分项结果（JSON），支持一键重放 |
| 闯关成绩 | `quiz_scores` | 每次作答一条；排行榜按用户取最佳 |
| 每日打卡 | `checkins` | 用户 + 自然日唯一（幂等），连续天数从今天或昨天往前数 |
| 问答板 | `qa_posts` / `qa_replies` | 发帖 + 回复，只追加不删除 |

**技术取舍**：不用 ORM、不用迁移工具——单文件原生 `sqlite3` + 启动时 `CREATE TABLE IF NOT EXISTS`，
依赖面最小（仅 Flask），Windows 本地可直接 `python -m server.server` 运行。

### 8.2 双模式优雅降级

- `assets/js/api.js` 启动时探测 `GET /api/health`；`file://` 协议下不发探测请求（避免 CORS 噪音），直接判离线。
- 后端在线：全局 `LJ.API.state.backend = true`，解锁全部在线功能；右上角徽章显示登录态。
- 后端离线：五模块照常纯前端演示；档案页显示「本地引擎模式」说明卡，引导启动后端。
- 所有在线操作用 `.catch()` 静默降级——网络异常不影响本地演示主流程。

### 8.3 安全设计（课程演示级别，但按真实工程的底线要求）

1. **口令存储**：`pbkdf2:sha256:200000$salt$hash` 三段式，随机 16 字节盐，绝不存明文；`verify_password` 按 `$` 拆 3 段（曾因写成 4 段导致恒假，已修复并有单测覆盖）。
2. **属主校验**：体检/计算历史按 `(id, user_id)` 联合查询，跨用户读/删一律 404，杜绝越权。
3. **幂等与冲突**：打卡按自然日唯一，重复打卡返回 `already: true`；闯关成绩每次作答追加一条（不覆盖历史）。
4. **输入约束**：合同文本 ≤100KB、标题 ≤40 字、问答标题 ≤60 字 / 内容 ≤2000 字 / 回复 ≤1000 字，前后端双重校验。
5. **会话**：Flask session（SECRET_KEY），`login_required` 装饰器保护写接口；`GET /api/quiz/leaderboard`、`GET /api/qa` 允许匿名浏览（学习产品应可浏览）。

### 8.4 前端接线（M7–M9）

- **M7 认证**：注册（昵称可选）/登录/登出；徽章状态三态（本地引擎模式 / 未登录 / 用户名）。
- **M8 学习闭环**：体检与计算完成后自动保存；档案页并行加载五路数据（打卡/成绩/体检/计算/排行榜）渲染统计卡；打卡按钮即时刷新连续天数；历史记录支持「重放」（载入原文/输入自动重跑）与删除；排行榜高亮当前用户。（修复：`api.js` 导出对象曾漏 `getCalc` 函数定义导致 IIFE 抛 ReferenceError、整个 `LJ.API` 未初始化——e2e 探针抓出后补回。）
- **M9 问答板**：匿名可浏览，登录可发帖/回复；回复区逐帖展开；提交后整板重新拉取。

### 8.5 v2 验收补充

10. 维权导航 6 类纠纷各自出专属路线（差异度断言见 tests/e2e_roadmap.py）；UI 设计令牌与 0 emoji 断言见 tests/probe_ui.py。

## 九、S1–S3 优化迭代（2026-10-11）

按「设计 → 评估 → 计划 → 实现 → 测试」小步循环推进，本轮立三项：内容差异度、维权导航差异化、UI 极简重设计。

### 9.1 S1 评估：差异度审计（设计/评估）

对六大模块逐项审计「是否只是同一种交互换个标题」。结论：**维权导航是差异度重灾区**——6 类纠纷共用一套「协商→调解→仲裁→诉讼」时间线，仅文案不同，处理方式高度一致，既不符合真实维权流程（欠薪可行政投诉/支付令、工伤须行政认定前置、社保走行政补缴），演示价值也大打折扣。其余模块（体检/计算/闯关/速查）各有独立规则与数据，差异度达标。

### 9.2 S2 实现：维权导航差异化（`assets/js/roadmap-data.js` + `app.js`）

`roadmap-data.js` 重写为 6 类纠纷专属 route：

| 未签合同 | 4 | 二倍工资仲裁时效逐月起算、补签主张 |
